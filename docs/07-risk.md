# 风险评估与风控约束

> 本文件是**上线前的否决清单**：任一条 P0 未落实，不允许把系统用于真实工作流。

## 1. 风险分级定义

| 级别 | 定义 | 处理要求 |
|---|---|---|
| **P0** | 造成数据不可恢复损失、账号永久封禁、敏感信息外泄 | 必须消除，不可接受残留 |
| **P1** | 高概率功能失效、账号受限、体验严重受损 | 必须有缓解措施 + 监控 |
| **P2** | 局部不可用、需人工修复 | 记录并排期 |
| **P3** | 展示异常、日志丢失 | 可接受 |

---

## 2. P0 风险清单

### P0-1｜Executor 误操作导致数据丢失

| 项 | 内容 |
|---|---|
| 场景 | Agent 生成的 `file_write` 覆盖了重要源码；`shell_run` 执行了删除类命令 |
| 后果 | 不可逆数据损失 |
| 缓解 | ① 默认 `ALLOW_HIGH_RISK=false`；② 会话级高危授权；③ 路径/命令黑名单；④ 覆盖已存在文件强制 `require_confirm`；⑤ 执行前落备份（可选：写入前 copy 到 `.facp_bak/`） |
| 残留 | 用户显式开启高危后仍可能误操作 → 必须靠人工确认兜底 |
| 验收 | 未经双开关的 `file_write` 100% 被拒且有审计记录 |

### P0-2｜跨域敏感信息外泄

| 项 | 内容 |
|---|---|
| 场景 | 国内域会话的业务资料被派工到国际域节点 |
| 后果 | 合规风险、商业信息外泄 |
| 缓解 | ① 默认 `same-domain-only`；② 跨域需会话级二次确认；③ 审计钩子做关键词拦截；④ 跨域 payload 只落摘要不落全文 |
| 残留 | 用户主动开跨域且内容不含关键词时仍可能外泄 → 属于用户决策责任，需在弹窗明确告知 |
| 验收 | 未开跨域的跨域调用 100% 返回 `forbidden_cross_domain` |

### P0-3｜通用执行权被滥用（权限扩散）

| 项 | 内容 |
|---|---|
| 场景 | 某 App 的 Sidecar 获得通用桌面执行能力，或被注入恶意提示词后调用 Executor 做任意操作 |
| 后果 | 等于把整台电脑交给一个不可控的 LLM |
| 缓解 | ① Sidecar 与 Executor 职责物理隔离（不同进程、不同代码库）；② Executor 不接收"自然语言一步到位"的指令，必须是结构化 steps；③ `require_confirm` 策略对高危强制开启；④ Executor 不响应非注册节点 |
| 残留 | 提示词注入仍可能构造合法 steps 组合出危险操作 |
| 验收 | Executor 代码中不存在任何"根据一句话自动规划步骤"的逻辑 |

## 3. P1 风险清单

### P1-1｜模型账号风控（Claude 等国际账号）

| 项 | 内容 |
|---|---|
| 触发因素 | 数据中心 IP、时区/语言指纹不一致、高频自动注入、多账号共用出口、来源不明的支付方式、频繁多设备登录 |
| 澄清（重要） | **IP 不是唯一变量，也不存在"100% 纯净永不封号"**。任何厂商都在持续调整风控策略 |
| 缓解 | ① 国际域节点独立出口（`network_isolation_tag` 分组）；② 一节点一账号；③ 注入限速（`max_per_min=6`，`min_interval_ms=800`）；④ 禁止共用浏览器 profile；⑤ 请求节奏拟人化 |
| 监测 | 记录每个节点的失败率与异常码，出现 401/403 激增立即降频并人工介入 |
| 残留 | 无法保证不封号；只能降低概率与缩小影响面 |

### P1-2｜UI 自动化被识别 / 失效

| 项 | 内容 |
|---|---|
| 场景 | Tier3 注入被客户端检测为自动化；或 App 改版后控件树变化导致全部失效 |
| 缓解 | ① Tier3 默认关闭；② 优先 Tier1；③ 每次启动做 Tier 探测与降级；④ 单节点失败率超阈值自动停用 Tier3 并告警 |
| 验收 | `allow_ui_automation` 默认 false |

### P1-3｜调用风暴 / 死循环

| 项 | 内容 |
|---|---|
| 场景 | A→B→C→A 循环派工；或某 Agent 因回执不理想反复重试 |
| 缓解 | ① `call_depth` 硬上限；② 同 trace 内节点重复检测；③ 单节点失败熔断；④ 注入限速；⑤ 会话急停 |
| 验收 | 人为构造环形调用，5 层内必须被拒并留下 `depth_exceed` 记录 |

### P1-4｜会话定位错误（串号）

| 项 | 内容 |
|---|---|
| 场景 | `switch_session` 切错会话，A 项目的任务被注入到 B 项目对话里 |
| 后果 | 上下文污染，且事后难以发现 |
| 缓解 | ① 切换后强制断言"当前活动会话 == 目标"；② 会话标题统一前缀 `[FACP]`；③ 注入内容带 `[FACP:<fsid>]` 标记；④ Observer 链路页可对账 |
| 验收 | 定位失败必须返回 4007，不得"看起来切了"就当作成功 |

### P1-5｜焦点竞争（人在用电脑时）

| 项 | 内容 |
|---|---|
| 场景 | Executor 正在 `type_text`，用户切走窗口，文字打到别处 |
| 缓解 | ① 执行前校验前台窗口；② 关键步骤间加短延迟并复校；③ 建议 Executor 执行时在 Observer 显示"正在操作，请勿动鼠标键盘"的提示条（可选全局热键暂停） |

## 4. P2 / P3 风险

| 编号 | 级别 | 风险 | 缓解 |
|---|---|---|---|
| P2-1 | P2 | NATS 或 FSHub 挂掉，协作中断 | Sidecar 退化为单机模式，Agent 不再自动派工 |
| P2-2 | P2 | 本地 HTTP 接口被同机程序滥用 | token 鉴权 + 仅 127.0.0.1 |
| P2-3 | P2 | 日志/截图膨胀占满磁盘 | 保留天数 + 定期清理任务 |
| P2-4 | P2 | 密钥泄露（若把模型 API Key 存进 FACP） | **FACP 不持有任何厂商 API Key**，密钥留在各 App 内部 |
| P3-1 | P3 | Observer 展示错乱 | 旁路组件，不影响主链路 |
| P3-2 | P3 | 审计日志丢失 | 本地 SQLite + 定期备份 |

## 5. 多层刹车（必须全部可用）

| 层级 | 手段 | 生效范围 | 恢复方式 |
|---|---|---|---|
| L1 全局 | 停止 NATS / 全局急停 | 全部协作 | 重启总线 |
| L2 会话 | `fsid.user_suspend = true` | 该会话所有新 CALL | Observer 关闭 |
| L3 节点 | Registry 标记 `disable` | 该节点不再被寻址/接收 | 重新启用 |
| L4 执行 | Executor 全局急停 | 立即终止正在执行的 tasks | 手动恢复 |
| L5 人工 | 单条 CALL 拒绝 / 人工确认弹窗 | 单次操作 | — |

> **验收要求**：五个刹车逐个演练一遍，每个都要能在 10 秒内生效。

## 7. 风险接受声明

以下风险**明确接受**，不再作为阻塞项：

1. 无法保证任何国际账号不被封禁 —— 只降低概率、隔离影响。
2. 闭源 App 无 API 时，读取会话产出摘要的能力受限 —— 以 Tier2 剪贴板或人工摘录兜底。
3. 跨域协作的合规责任最终归属用户 —— 系统提供审计与拦截，不替代用户判断。
4. UIA 在部分自绘界面上不可用 —— 该场景直接判定为"不支持"，不做像素级妥协。
